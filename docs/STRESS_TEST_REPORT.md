## Notes and known limits

- Instructions execute **sequentially, in dependency order** (ties keep the authored order), inside one git transaction. The 50-instruction run is a throughput and safety test, not a parallel one; deterministic ordering is a deliberate engine invariant.
- `rename_symbol` raises Jedi's built-in project-search budget for the duration of the search. Jedi otherwise stops after 30 parsed files and silently leaves call sites unrenamed; the fix is covered by a regression test with 32 modules.
- The rename atom does not reorder imports by design. Bombing A uses names that preserve isort order (`AbstractEntity`, `verify_record`), so the project's ruff isort gate remains a real gate rather than a silenced one.
- The AST scope guard fingerprints every function, class and module-level statement before the plan and re-verifies every changed file afterwards; imports are excluded because the import atoms are allowed to rewrite them.
- `docs/STRESS_TEST_REPORT.md` is generated evidence and is intentionally kept in the repository. Re-run the harness to refresh every number.
